# R10 — IRI's: gezaghebbend, stabiel, niet in andermans namespace

!!! regel "In het kort"
    - productiedata: de gezaghebbende basis-IRI van het domein;
    - illustratieve voorbeelden: deelpaden van `https://example.org/`, met betekenisvolle namen;
    - geen blanco knoop voor wat van buitenaf aanspreekbaar moet zijn;
    - grote datasets: deterministische skolem-IRI's voor intervallen, tijdstippen, resultaten en
      geometrieën, afgeleid van de ouder;
    - scripts leiden IRI's af van een deterministische sleutel, nooit van een willekeurige waarde;
    - geen nieuwe resources in de namespace van een geladen vocabularium.

## Waarom

Een IRI is een belofte: *hier kan je naar verwijzen*. Een blanco knoop kan niet aangesproken
worden van buiten het bestand. Een IRI die bij elke run van een script verandert, kan niet het
doel van een verwijzing zijn en breekt een versieketen. Een IRI in de namespace van een ander
(`unit:EUR` in QUDT) is een uitspraak die je niet mag doen: de eigenaar van de namespace bepaalt
wat erin bestaat.

## Goed

```turtle
@prefix sensor: <https://aquafin.be/id/sensor/> .
sensor:4c314f066bea53f212495cb8c1eaca0b a sosa:Sensor .   # MD5 van het toestelnummer

ex:uurtelling-08 sosa:phenomenonTime ex:interval-uurtelling-08 .   # skolem-IRI in een gescripte dataset
```

## Fout

```sparql
BIND(IRI(CONCAT("https://aquafin.be/id/sensor/", STRUUID())) AS ?sensor)   # elke run anders
```

```turtle
unit:EUR a qudt:Unit .                       # gemunt in de namespace van QUDT
ex:waarneming sosa:madeBySensor [ a sosa:Sensor ] .   # een sensor waarnaar niemand kan verwijzen
```
