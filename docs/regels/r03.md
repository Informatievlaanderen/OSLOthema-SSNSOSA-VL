# R3 — Een resultaat met eenheid is een `qudt:QuantityValue`

!!! regel "In het kort"
    Een numeriek resultaat met een fysische eenheid is een `qudt:QuantityValue` met
    `qudt:numericValue` en `qudt:hasUnit`. Niet `sosa:Result` (verouderd), niet `qudt:value`. De
    eenheid komt uit QUDT, of uit een domeinregister (CSOR) wanneer QUDT ze niet kan uitdrukken;
    één keuze per voorbeeld. Een waarde onder de rapportagegrens heeft geen `numericValue`, maar
    `qudt:lowerBound` en `qudt:upperBound`.

## Waarom

- **De eenheid hoort bij de waarde.** Niet bij de eigenschap, niet bij het datatype.
- **Een resource kan inputwaarde zijn.** Afgeleide waarnemingen verwijzen naar resultaten
  ([R7](r07.md)); een literal kan dat niet.
- **Het past in de kaart.** `sosa:hasResult ⊂ prov:generated` maakt elk resultaat een
  `prov:Entity`; een `qudt:QuantityValue` is dat ([SOSA en QUDT](../kaart/sosa-qudt.md)).
- **`sosa:Result` voegt niets toe**: SSN/SOSA 2023 verklaart het verouderd, en het type
  `prov:Entity` volgt al uit de alignment.

## Goed

```turtle
ex:waarneming sosa:hasResult [
    a qudt:QuantityValue ;
    qudt:numericValue 2.4 ;
    qudt:hasUnit unit:M3
] .

# met een register-eenheid
ex:resultaat-p a qudt:QuantityValue ;
    qudt:numericValue 0.42 ;
    qudt:hasUnit csor-eenheid:E_131 .     # mg P/L; mapping naar QUDT staat in het register

# onder de rapportagegrens
ex:resultaat-pfos a qudt:QuantityValue ;
    qudt:lowerBound 0.0 ;
    qudt:upperBound 0.0125 ;
    qudt:hasUnit unit:MicroGM-PER-L .
```

## Fout

```turtle
ex:waarneming sosa:hasResult [
    a sosa:Result ;          # verouderd
    qudt:value 2.4 ;         # bestaat, maar is niet het patroon
    qudt:unit unit:M3        # bestaat niet
] .
ex:resultaat-pfos qudt:numericValue 0.0125 .   # "< 0,0125" als meting van 0,0125
```

## Register-eenheden

- vind de eenheid in het register; het register kent de mapping naar QUDT (`skos:exactMatch`,
  `skos:broadMatch`); vermeld die in de bespreking;
- zet **geen** SKOS-mappings in de data;
- beschrijft de data de eenheid (met de klasse van het register), type ze dan ook `qudt:Unit`;
- QUDT vraagt van elke eenheid een grootheidssoort en een dimensievector; het profiel versoepelt
  dat met `owl:minCardinality 0` op `qudt:Unit`.

Uitgewerkt in [Register en QUDT](../kaart/register-qudt.md).

## Een eigen klasse voor resultaten

Een profiel dat een eigen klasse wil, maakt ze subklasse van `qudt:QuantityValue` (zoals
`wk:Meetresultaat`), en de data typeert beide.

## In de casussen

- [Erosiepoel](../casussen/erosiepoel.md): `qudt:unit` → `qudt:hasUnit`.
- [Waterkwaliteit](../casussen/waterkwaliteit.md): CSOR-eenheden, rapportagegrens.
- [Geluidsmeetnet](../casussen/geluidsmeetnet.md): één stijl, `unit:DeciB_A` en `unit:SEC`.
